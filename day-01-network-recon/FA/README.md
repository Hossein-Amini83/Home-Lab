# روز 01 — شناسایی اولیه شبکه

## 1. سناریو

یک شرکت فرضی کوچک از من خواسته است پیش از شروع تست نفوذ، وضعیت اولیه شبکه داخلی خود را بررسی کنم. مستندات شبکه ناقص است و تیم IT فقط محدوده شبکه آزمایشگاه را در اختیارم گذاشته است.

وظیفه من این است که مشخص کنم کدام میزبان‌ها در شبکه آزمایشگاهی پاسخ‌گو هستند و کدام پورت‌ها روی یکی از سرورهای شناسایی‌شده در دسترس‌اند.

## 2. محدوده

با دستور `ip a` آدرس‌های شبکه ماشین مهاجم (Kali Linux) را بررسی کردم. علاوه بر رابط `loopback`، دو رابط شبکه شناسایی شد:

| رابط | آدرس IPv4 | آدرس Broadcast | نوع شبکه |
|---|---|---|---|
| `eth0` | `192.168.56.102/24` | `192.168.56.255` | شبکه داخلی آزمایشگاه (Host-Only) |
| `eth1` | `10.0.3.15/24` | `10.0.3.255` | NAT، طبق تنظیمات ماشین مجازی |

محدوده آدرس‌های قابل‌استفاده در هر زیرشبکه:

- `eth0`: از `192.168.56.1` تا `192.168.56.254`
- `eth1`: از `10.0.3.1` تا `10.0.3.254`

> محدوده‌های بالا بر اساس ماسک `/24` محاسبه شده‌اند؛ این موضوع به معنی فعال بودن همه آدرس‌ها نیست. اسکن این تمرین به شبکه Host-Only محدود است.

## 3. هدف

میزبان هدف را شناسایی کنم و گزارشی از پورت‌های TCP باز و سرویس‌های قابل‌شناسایی آن تهیه کنم. در این تمرین نیازی به ورود به سیستم هدف یا بهره‌برداری از آسیب‌پذیری نیست.

## 4. ابزارهای مورد استفاده

- Nmap
- ابزارهای داخلی لینوکس برای مشاهده تنظیمات شبکه، از جمله `ip`

## 5. شناسایی شبکه (Reconnaissance)

- `eth0`: رابط متصل به شبکه Host-Only آزمایشگاه
- `eth1`: رابط NAT، طبق تنظیمات ماشین مجازی
- محدوده شبکه Host-Only: `192.168.56.0/24`
- محدوده شبکه NAT: `10.0.3.0/24`

## 6. کشف میزبان (Host Discovery)

**دستور استفاده‌شده:**

```bash
nmap -sn 192.168.56.0/24 -n
```

**میزبان‌های مشاهده‌شده یا شناسایی‌شده:**

1. `192.168.56.1` — احتمالاً رابط میزبان یا سرویس شبکه Host-Only؛ نقش دقیق آن باید با تنظیمات شبکه تأیید شود.
2. `192.168.56.102` — ماشین Kali Linux؛ آدرس آن با `ip a` تأیید شد.
3. `192.168.56.101` — هدف احتمالی، Metasploitable 2.
4. `192.168.56.100` — آدرس مربوط به یک ماشین مجازی دیگر که طبق وضعیت ماشین‌های مجازی خاموش بوده است؛ اسکن به‌تنهایی خاموش بودن آن را اثبات نمی‌کند.

**هدف انتخاب‌شده:** Metasploitable 2 (`192.168.56.101`)

**دلیل انتخاب:** خروجی تشخیص سیستم‌عامل Nmap با دستور زیر با سیستم‌عامل مورد انتظار هدف سازگار بود. تشخیص سیستم‌عامل به‌تنهایی هویت ماشین را قطعی نمی‌کند.

```bash
nmap -O 192.168.56.101
```

## 7. اسکن پورت (Port Scanning)

**دستور استفاده‌شده:**

```bash
nmap -sV 192.168.56.101
```

این اسکن برای بررسی پورت‌های TCP منتخب و شناسایی سرویس‌ها و نسخه‌های احتمالی آن‌ها استفاده شد. نتایج زیر بر اساس خروجی ثبت‌شده از Nmap هستند.

| پورت | وضعیت | سرویس | نسخه یا اطلاعات گزارش‌شده |
|---|---|---|---|
| `21/tcp` | Open | FTP | vsftpd 2.3.4 |
| `22/tcp` | Open | SSH | OpenSSH 4.7p1 Debian 8Ubuntu1 (protocol 2.0) |
| `23/tcp` | Open | Telnet | Linux telnetd |
| `25/tcp` | Open | SMTP | Postfix smtpd |
| `53/tcp` | Open | DNS / DOMAIN | ISC BIND 9.4.2 |
| `80/tcp` | Open | HTTP | Apache httpd 2.2.8 ((Ubuntu) DAV/2) |
| `111/tcp` | Open | RPCBind | 2 (RPC #100000) |
| `139/tcp` | Open | NetBIOS-SSN | Samba smbd 3.X–4.X (workgroup: WORKGROUP) |
| `445/tcp` | Open | SMB / NetBIOS-SSN | Samba smbd 3.X–4.X (workgroup: WORKGROUP) |
| `512/tcp` | Open | exec | netkit-rshd |
| `513/tcp` | Open | login | OpenBSD یا Solaris rlogind (تشخیص احتمالی) |
| `514/tcp` | Open | shell | netkit-rshd |
| `1099/tcp` | Open | RMI Registry | GNU Classpath grmiregistry |
| `1524/tcp` | Open | bindshell | در خروجی Nmap با عنوان Metasploitable root shell شناسایی شد |
| `2049/tcp` | Open | NFS | نسخه 2–4 (طبق خروجی ثبت‌شده) |
| `2121/tcp` | Open | FTP | ProFTPD 1.3.1 |
| `3306/tcp` | Open | MySQL | 5.0.51a-3ubuntu5 |
| `5432/tcp` | Open | PostgreSQL | DB 8.3.0–8.3.7 |
| `5900/tcp` | Open | VNC | protocol 3.3 |
| `6000/tcp` | Open | X11 | Access denied |
| `6667/tcp` | Open | IRC | UnrealIRCd (املای دقیق نام محصول در خروجی اصلی بررسی شود) |
| `8009/tcp` | Open | AJP13 | Apache JServ (protocol v1.3) |
| `8180/tcp` | Open | HTTP / Tomcat | Apache Tomcat/Coyote JSP engine 1.1 |

> نام سرویس و نسخه‌ها همان اطلاعات گزارش‌شده توسط Nmap هستند و ممکن است در بعضی موارد تخمینی باشند. برای انتشار نهایی، بهتر است جدول با خروجی خام Nmap تطبیق داده شود. وجود پورت باز یا نمایش یک نسخه به‌تنهایی اثبات آسیب‌پذیری نیست.

## 8. یافته‌ها

- **یافته‌های تأییدشده:** میزبان `192.168.56.101` در شبکه آزمایشگاه پاسخ‌گو بود و اسکن Nmap پورت‌های TCP بالا را به‌صورت `open` گزارش کرد.
- **فرضیه‌های تأییدنشده:** احتمال وجود ریسک در برخی سرویس‌های قدیمی یا در دسترس شبکه؛ هنوز آسیب‌پذیری هیچ‌کدام از سرویس‌ها آزمایش و تأیید نشده است.
- **نگرانی‌های امنیتی بالقوه:** تعداد زیاد سرویس‌های در دسترس، از جمله سرویس‌های قدیمی دسترسی از راه دور و سرویس‌های پایگاه داده. لازم است ضرورت دسترسی شبکه‌ای و پیکربندی آن‌ها در مراحل بعد بررسی شود.

## 9. محدودیت‌ها

- این تمرین بر شناسایی میزبان و اسکن پورت‌های TCP متمرکز بود.
- پورت‌های UDP بررسی نشدند.
- احراز هویت، کنترل دسترسی، پیکربندی سرویس‌ها و بهره‌برداری از آسیب‌پذیری‌ها بررسی نشدند.
- `nmap -sV` به‌طور پیش‌فرض همه پورت‌های TCP را اسکن نمی‌کند؛ بنابراین این نتایج نباید به‌عنوان فهرست قطعی تمام پورت‌های باز سیستم معرفی شوند.
- تشخیص سیستم‌عامل و نسخه سرویس‌ها ممکن است تخمینی باشد.

## 10. درس‌های آموخته‌شده

**چه چیزی یاد گرفتم؟**

یاد گرفتم با بررسی رابط‌های شبکه و آدرس‌های IP می‌توانم رابط متصل به شبکه آزمایشگاه را از رابط NAT تشخیص دهم. همچنین با Nmap میزبان‌های پاسخ‌گو و سرویس‌های قابل‌شناسایی را بررسی کردم.

**با چه مشکلی مواجه شدم؟**

در ابتدا چند آدرس IP و دو رابط شبکه داشتم و مشخص نبود هر آدرس به کدام شبکه یا ماشین مربوط است.

**چگونه مشکل را حل کردم؟**

با بررسی خروجی `ip a`، اجرای Nmap و جست‌وجو در مستندات و منابع آموزشی، اطلاعات شبکه را با وضعیت ماشین‌های مجازی تطبیق دادم.

## 11. نتیجه‌گیری

در این آزمایش، محدوده شبکه Host-Only مشخص شد و میزبان هدف احتمالی Metasploitable 2 با آدرس `192.168.56.101` انتخاب شد. اسکن Nmap چندین پورت TCP باز و سرویس‌های قابل‌شناسایی را گزارش کرد. این نتایج یک دید اولیه از سطح حمله شبکه‌ای فراهم می‌کنند؛ اما برای تأیید آسیب‌پذیری‌ها و تعیین میزان ریسک، به بررسی‌های تکمیلی نیاز است.
